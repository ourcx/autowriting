# Dashy 页面视觉方向

以 [Clay 规范](../../.codewiz/rules/DESIGN.md) 为基础。Dashy 的主要用户是要把素材整理成文章、检查排版、再交到发布平台的创作者。页面设计先回答一个问题：用户现在要做什么，完成后在哪里确认结果？

| 页面 | 首屏优先 | 表达方式 |
| --- | --- | --- |
| 首页、登录注册、首次设置 | 理解用途、进入工作台、完成必要配置 | 首页左文右图，用项目内容示意素材与发布预览；表单带可见标签，按实际步骤组织 |
| 工作台、编辑、画布、样式、预览 | 开始或继续写作，确认稿件在平台上的效果 | 新建和续写优先；编辑区与预览给正文留空间；工具按任务归组，手机上保留可触达的下一步 |
| 草稿、素材、提示词、知识库、定时任务、账号观察 | 查看当前状态，找到要处理的内容 | 用列表、细线和留白组织同类内容；没有数据时指出能执行的下一步 |
| 账号、AI 配置、用量、用户管理、系统监控 | 看清连接、配置与运行状态 | 对齐同类数据；颜色用于强调动作、识别平台或表达状态；同组数字可直接比较 |

界面以奶油底、近黑文字和主按钮为基调。标题用 500 字重，正文优先保证中文可读性。淡紫用于首页的产品示意和明确的选中状态；用户生成的文章主题、画布对齐网格和平台排版保留各自的视觉规则。动效只用于展开、状态变化和等待反馈，避免渐变底、毛玻璃、装饰动画和无事实依据的宣传数字。

评审先看桌面和手机的真实渲染，再检查入口、键盘焦点和操作反馈。第一轮之后只修截图能指明的问题，如正文被工具挤占、同一信息重复、主动作在窄屏不易触达。
