# 提示词可视化和配置指南

## 概述

提示词可视化功能让你能够集中管理、查看和编辑项目中使用的所有生成提示词。这个功能包括：

- **提示词库**：查看所有提示词（内置和自定义）
- **可视化编辑**：编辑提示词内容，支持实时预览
- **版本管理**：自动保存版本历史，支持恢复到任何历史版本
- **分类管理**：按功能分类组织提示词
- **使用统计**：追踪每个提示词的使用次数

## 访问提示词页面

在主导航栏中点击「提示词」按钮，或直接访问 `/prompts` 路由。

## 功能说明

### 1. 提示词列表

左侧面板显示所有提示词，支持：

- **搜索**：按名称或描述搜索提示词
- **分类过滤**：按功能分类筛选（文章生成、分析、编辑等）
- **快速创建**：点击「新建」按钮创建新提示词

### 2. 提示词详情

右侧面板显示选中提示词的详细信息：

- **基本信息**：名称、分类、版本、使用次数
- **内容**：完整的提示词文本
- **标签**：提示词的标签
- **时间戳**：创建和更新时间

### 3. 编辑提示词

点击「编辑」按钮进入编辑模式：

- **内容编辑**：修改提示词内容
- **实时预览**：右侧显示修改后的效果
- **变更说明**：记录这次修改的原因（可选）
- **版本自动保存**：修改时自动创建新版本

### 4. 版本管理

点击「版本历史」按钮查看所有历史版本：

- **版本列表**：显示所有版本及修改说明
- **版本恢复**：点击「恢复此版本」回到任何历史版本
- **变更追踪**：每个版本都记录了修改时间和说明

### 5. 统计信息

顶部统计栏显示：

- **总提示词数**：库中的提示词总数
- **内置提示词**：系统内置的提示词数
- **自定义提示词**：用户创建的提示词数
- **总使用次数**：所有提示词的累计使用次数

## 内置提示词

系统预置了以下提示词：

### 文章生成
- **ID**: `prompt-article-generate`
- **用途**：生成完整的文章内容
- **特点**：结合 AGENTS.md 规范和用户任务要求

### 文章分析
- **ID**: `prompt-article-analyze`
- **用途**：分析文章质量，检查规范符合度
- **输出**：JSON 格式的分析结果

### 内联编辑
四种编辑操作的提示词：

1. **润色** (`prompt-edit-polish`)
   - 去掉 AI 感、套话、被动句
   
2. **精简** (`prompt-edit-shorten`)
   - 精简到 60% 以内，保留核心信息
   
3. **扩展** (`prompt-edit-expand`)
   - 补充案例和数据，增强说服力
   
4. **重写开头** (`prompt-edit-rewrite-lead`)
   - 重写开头，直接切入主题

### 大纲生成
- **ID**: `prompt-outline-generate`
- **用途**：根据任务生成文章大纲
- **输出**：Markdown 格式的大纲

### 素材整理
- **ID**: `prompt-materials-organize`
- **用途**：将原始素材结构化
- **输出**：核心数据、观点、案例等

### 样式生成
- **ID**: `prompt-style-generate`
- **用途**：生成微信兼容的 CSS 样式
- **约束**：遵循微信渲染器限制

### 封面生成
- **ID**: `prompt-cover-generate`
- **用途**：生成文章封面的图像提示词
- **规格**：2.35:1 宽屏比例

## 创建自定义提示词

### 步骤

1. 点击「新建」按钮
2. 填写基本信息：
   - **名称**：提示词的名称（必填）
   - **分类**：选择功能分类（必填）
   - **描述**：简短描述（可选）
3. 编写提示词内容（必填）
4. 点击「保存」

### 最佳实践

- **清晰的指令**：用清晰的语言描述任务
- **具体的要求**：列出具体的要求和约束
- **输出格式**：明确指定输出格式
- **示例**：如果可能，提供示例
- **版本控制**：修改时添加变更说明

## API 接口

### 获取所有提示词
```
GET /api/prompts/list
```

### 按分类获取提示词
```
GET /api/prompts/category/:category
```

### 获取单个提示词
```
GET /api/prompts/:id
```

### 创建提示词
```
POST /api/prompts/create
Body: {
  name: string,
  category: string,
  description?: string,
  content: string,
  tags?: string[]
}
```

### 更新提示词
```
POST /api/prompts/:id/update
Body: {
  content: string,
  changeNote?: string
}
```

### 删除提示词
```
POST /api/prompts/:id/delete
```

### 获取版本历史
```
GET /api/prompts/:id/versions
```

### 恢复到特定版本
```
POST /api/prompts/:id/restore/:version
```

### 获取统计信息
```
GET /api/prompts/stats/summary
```

## 数据库结构

### prompts 表
存储提示词的当前版本：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT | 提示词 ID |
| name | TEXT | 提示词名称 |
| category | TEXT | 分类 |
| description | TEXT | 描述 |
| content | TEXT | 提示词内容 |
| version | INTEGER | 当前版本号 |
| tags | TEXT | 标签（JSON 数组） |
| is_builtin | INTEGER | 是否内置 |
| usage_count | INTEGER | 使用次数 |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间 |

### prompt_versions 表
存储提示词的版本历史：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT | 版本记录 ID |
| prompt_id | TEXT | 提示词 ID |
| version | INTEGER | 版本号 |
| content | TEXT | 该版本的内容 |
| change_note | TEXT | 变更说明 |
| created_at | TEXT | 创建时间 |

## 常见问题

### Q: 能否修改内置提示词？
A: 不能直接修改内置提示词，但可以创建新的自定义提示词。如果需要修改内置提示词，请联系管理员。

### Q: 版本历史会一直保存吗？
A: 是的，所有版本历史都会永久保存在数据库中。

### Q: 如何导出提示词？
A: 可以复制提示词内容，或通过 API 获取 JSON 格式的数据。

### Q: 提示词的使用次数是如何统计的？
A: 每次通过 API 获取提示词时，使用次数会自动增加 1。

### Q: 能否批量导入提示词？
A: 目前需要逐个创建，但可以通过 API 批量导入。

## 集成到其他功能

提示词可以集成到以下功能中：

在生成文章时，自动使用对应的提示词。

### 文章分析
使用「文章分析」提示词检查文章质量。

### 内联编辑
在编辑器中使用四种编辑提示词。

### 大纲生成
根据任务生成文章大纲。

整理和结构化素材。

## 最佳实践

1. **定期审查**：定期审查和更新提示词，确保质量
2. **版本控制**：修改时添加清晰的变更说明
3. **分类管理**：为提示词添加合适的分类和标签
4. **文档化**：为复杂的提示词添加详细的描述
5. **测试**：修改后测试提示词的效果
6. **备份**：重要的提示词修改前做好备份

## 故障排除

### 提示词不显示
- 检查网络连接
- 刷新页面
- 检查浏览器控制台是否有错误

### 修改后没有保存
- 确保点击了「保存」按钮
- 检查是否有错误提示
- 查看版本历史确认是否已保存

### 版本恢复失败
- 确保提示词不是内置的
- 检查网络连接
- 尝试刷新页面后重试
