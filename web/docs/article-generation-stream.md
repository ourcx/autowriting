# 普通文章生成的 SSE 保活

公众号与今日头条共用 `POST /api/articles/:articleId/generate/stream`。检索、模型思考以及两个平台切换期间可能长时间没有正文输出。仅发送响应头无法重置代理后续的读取空闲计时，用户会在连接被切断后看到 `network error`。

该路由现在在响应头发出后立即启动保活，每 15 秒写入一次 SSE 注释 `: heartbeat`。注释不触发业务事件，不改变原有 `status/chunk/done/error` 协议，也不进入保存的文章正文。响应结束或客户端连接关闭后清理定时器。实现不修改鉴权、数据库、文件路径或文章写入方式。

## 回归

`pnpm --dir web smoke` 包含真实生成接口的双平台回归：本地模拟模型延迟输出，经过空闲 20 秒就断开的代理，验证心跳、两平台的完成事件与保存后的完整正文。账号和文件均由原有 smoke 框架写入系统临时目录并清理，不访问真实 AI 服务。

复现超过常见 60 秒代理空闲窗口的等待：

```bash
SMOKE_PORT=3107 SMOKE_STREAM_DELAY_MS=65000 pnpm --dir web smoke
```

此时公众号模型等待 65 秒，头条模型等待 16 秒；默认两次等待均为 16 秒。

上线需要发布后端代码并按现有方式重启服务。无需新增配置。该修复处理无数据期间的空闲断连；真实模型错误、服务不可达或代理的绝对请求时长限制仍需分别排查。
