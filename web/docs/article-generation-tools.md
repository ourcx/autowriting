# 文章生成：网页工具、配图与验证码

生成候选稿时，AI 可以搜索公开资料、打开动态网页、点击链接、展开内容、滚动加载、提取原图、截取真实页面，并使用临时终端整理已抓取的 HTML 和正文。工具结果回到本次调研，再用于提纲和正文；生成轨迹里可以看到执行结果。

## 使用入口

打开文章的“生成候选稿”，选择平台、文章形式、候选数量、配图方式和目标图片数。

| 选项 | 行为 |
| --- | --- |
| 正常图文 | 按正常文章结构写作，默认目标 3 张图 |
| 多图少字 | 默认目标 6 张图，要求模型至少配 2 张；正文以 300–600 字为目标，缺图和篇幅不合格不会中断正文生成 |
| 只用真实图片 | 默认选择。采集原网页照片、官方图、原始图表或真实页面截图；图片不足就提示缺图 |
| 真实优先，允许 AI 补图 | 本次明确授予图片生成权限。真实图片不足时，可以调用官方 GPT Image |
| 不配图 | 正常文章模式下只生成正文 |

配图目标可选 2–8 张，两张是选图提示词的底线要求，不作为阻断正文的条件。优先下载网页原图，截图作为补充；先下载并读取候选图片的实际内容，把缩略图交给本次模型选择，再保存选中的原图并插入正文。选图需要本次模型支持图片输入。实际图片必须与文章有关，数量不足时不会伪造 URL、放占位图或擅自生成。

AI 生成的图片会标为“AI 生成示意图”。原始发布页面链接只保存在后台配图信息与调研轨迹，正文不写来源或参考资料。图片下载并保存到 `DATA_DIR/uploads`，候选稿正文引用保存后的文件，因此不依赖原站持续允许图片外链。

浏览器和终端默认开启，可以在本次生成设置中关闭。它们只在当前文章生成过程中使用。

正文编辑区的“图文”模式使用 Tiptap 富文本库，图片直接显示，选区、光标和撤销由库处理。支持上传、粘贴和拖入图片；选中图片后可删除，修改图片链接可切换到原生文本框的“Markdown”模式。选中文字仍可使用 AI 润色。切换显示方式不会改写已保存的正文。

## 官方 OpenAI 图片配置

在 AI 配置的封面服务中选择“GPT Image 官方”，填写官方图片模型 ID。默认模型为 `gpt-image-2`，也可按当前账号已开通的模型填写其他 `gpt-image-*` ID。

图片请求固定发送到：

```text
https://api.openai.com/v1/images/generations
```

请求由当前浏览器执行，沿用已有的浏览器模型连接。生成过程中保持页面打开，并确保浏览器可以访问官方 API。

“OpenAI API Key”留空时复用文章 Key。文章使用官方 OpenAI、封面选择其他服务时，正文 GPT Image 请求优先复用官方文章 Key。文章模型与图片模型分别配置，选择文章模型不会自动替换图片模型。

只有本次候选稿的 `imageMode` 明确为 `generate` 时，正文配图流程才允许发起图片生成。默认值为 `web`；旧版 `auto` 参数也按 `web` 处理。服务端配置一个图片模型或 Key，不代表本次已授权生成图片。

## 浏览器环境

浏览器工具复用项目的 Playwright，使用独立的匿名 Chromium 上下文。部署环境需提前安装浏览器及系统依赖：

```bash
cd web
pnpm exec playwright install chromium
```

Linux 环境可使用 Playwright 的系统依赖安装命令：

```bash
pnpm exec playwright install --with-deps chromium
```

浏览器只读取公网 HTTP/HTTPS 地址。模型打开的网址必须来自搜索结果、用户提供的公开链接或刚读到的页面链接。浏览器可以点击链接与展开内容，不使用作者已有的登录资料，也不执行发布、购买等业务操作。

## AI 处理网页验证码

浏览器识别到可见的人机验证页面后，会把当前截图和页面提示交给本次文章模型，让模型选择点选、填写图形验证码、拖动滑块或等待。每次操作后重新读取页面状态，确认验证是否消失；通过后继续采集。

验证码处理需要当前模型支持图片输入。处理流程最多执行 8 步，失败会出现在“AI 处理网页验证码”轨迹中，验证码页面不会被当作已读正文，也不会作为文章配图。

验证截图只在本次请求中用于识别，不加入候选稿图片库。当前匿名网页设置的 Cookie 只保留在临时浏览器内存中。验证码所需的提交仅允许发往当前站点或已识别的验证码服务；普通页面仍以读取为主。模型不会填写密码、短信码或个人资料。

该能力是自动尝试处理，不能保证每种验证都能通过。需要扫码、账号登录或模型无法识别的页面会保留失败结果，继续利用其他已读来源。

## 临时终端

服务端需已安装并启动 Docker，并提前准备终端镜像：

```bash
docker pull python:3.12-slim
```

可以用环境变量指定已准备好的镜像：

```dotenv
WRITING_TERMINAL_IMAGE=python:3.12-slim
```

镜像需包含 `python3` 和 `/bin/sh`。生成请求不会自动拉取镜像或安装依赖。

每篇候选稿有自己的临时容器，工作目录为 `/work`。已抓取的页面会写成 `page-*.html` 和 `page-*.txt`；模型可用 Python 标准库与 Shell 搜索、解析、去重和整理这些文件。终端输出只用于解释已读资料，新增事实仍须引用原始网页。

容器没有宿主目录挂载、Docker socket、作者 Cookie 或模型 Key。网络关闭，公开网页由浏览器和网页读取工具采集。容器使用非 root 用户、只读系统盘、1 核 CPU、256 MB 内存和临时文件目录；单次命令最多运行 30 秒。停止生成或结束请求时回收容器。

Docker 不可用时，轨迹会显示终端失败，AI 可以继续使用网页读取与浏览器结果。

## 中断与恢复

正文、已保存的配图、调研来源和执行轨迹随候选稿保存。恢复生成时复用已有正文、提纲和图片。

配图处理开始前会保存状态。点击重试会重新采集缺少的真实图片，已保存的原图不重复插入。图片生成失败、超时或用户取消后，不在同一候选稿中重复可能计费的生成请求，恢复时只补采真实图片。

单篇生成总时限为 30 分钟，浏览器模型连接时限为 35 分钟。真实图片不会因下载失败而转成 AI 图片。正文优化后会补回已保存图片并清理来源图注。配图失败、图片不足或未达到目标篇幅都不阻断正文生成。

## 实现入口

- `server/utils/candidateGeneration.ts`：串联调研、工具、配图、流式正文与候选稿保存。
- `server/articleWritingAgent.ts`：根据实际工具结果选择下一步动作。
- `server/writingTools.ts`：匿名浏览器、验证码操作与临时终端。
- `server/articleImages.ts`：选择原图、保存图片、插入正文及保存后台出处。
- `server/utils/openaiImage.ts`：官方 GPT Image 图片请求。
- `src/components/GenerateModal/`：生成设置、正文配图预览与执行轨迹。
