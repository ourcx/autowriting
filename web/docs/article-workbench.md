# 文章工作台与发布耗时指标

文章编辑器的主流程统一为“任务 → 素材 → 写作 → 审核 → 发布”。今日头条、小红书、封面和图片库属于平台与素材辅助能力，不参与公众号主流程完成度。公众号样式预览、封面选择和草稿推送直接在编辑器的发布阶段完成；原独立预览页继续保留，供需要更大画布时使用。

每篇服务端文章在正文同目录保存 `article_workflow*.json`，不修改 SQLite。文件只记录流程时间，不保存正文或凭据：

- `createdAt`：已有文章取现有文件最早创建时间，新文章取第一次打开时间。
- `firstGeneratedAt`：首次形成有效正文。
- `lastReviewedAt`：最近一次 AI 深度审核完成时间。
- `wechatDraftOpenedAt`：首次进入公众号发布阶段。
- `wechatDraftAt`：微信草稿接口成功后由工作台记录。

核心指标为 `wechatDraftAt - createdAt` 的中位数。上线前记录至少一周基线，上线后按相同账号与文章类型观察两周；目标降低 30%。护栏指标为微信草稿推送成功率、文章最终发布率和生成后正文保留比例，避免单纯缩短耗时造成质量下降。

本地文章的工作流时间保存在浏览器 `localStorage`，迁移到服务端后按服务端文章重新记录。历史文章没有工作流文件时会根据任务、素材、正文与已有文件时间推导当前阶段，不改写正文。

本地规范核查会读取本篇任务中的目标字数、第一人称要求、`不要提到/出现/使用` 的词语和 emoji 限制。任务要求优先于默认写作偏好。

验证命令：

```bash
pnpm --dir web smoke
pnpm --dir web dev --host 127.0.0.1
node web/scripts/test-article-workbench.mjs
```

浏览器回归使用内存接口，不写用户文章，不调用真实模型或公众号。真实微信草稿推送仍需在目标账号验证。
