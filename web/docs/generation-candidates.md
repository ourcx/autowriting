# 多候选文章生成

生成弹窗默认生成一篇，可选择两篇或三篇，也可一次生成“公众号 + 今日头条”成对方案。同一批同平台候选稿会并发生成；双平台方案使用同一份任务和素材并行成稿。单独改写头条版时可以传入已有公众号母稿。每个用户最多并发六篇，全进程最多并发十二篇。候选稿单独保存，用户选中后才通过现有文章保存接口写入正文。公众号原文仍由 `writeArticleSafely` 在替换前备份。

文章工作台把“下一步”和“生成候选稿”分开处理。任务和素材只要非空就能继续进入写作，不再使用隐藏字数门槛；素材、写作和审核阶段始终保留候选稿入口。已有正文时按钮显示“继续生成候选稿”，打开候选池不会覆盖正文，只有用户明确选用某篇候选稿后才保存。

这里使用异步网络并发，不使用 Worker Thread。模型调用的主要耗时是等待网络返回；线程留给本地 Embedding 和 HNSW 索引构建等 CPU 密集任务。具体区别见[并发与 Worker Thread](concurrency-and-workers.md)。

## 操作路径

打开文章并进入生成候选稿弹窗，选好平台和候选数量后开始。每篇候选独立显示状态、字数和执行轨迹。生成时默认打开“生成轨迹”，可点击时间条或步骤查看输入、结果、来源链接和耗时；用“正文”查看草稿，用“对比全文”查看同批候选。旧候选如果没有记录，会显示空轨迹。

文章 Agent 从知识库和当前保存的正文自动检索作者自己的旧文，作为表达样本。联网服务可用时先提交选题的公开关键词，再尝试打开来源。调研过程中可查找原素材、定位网页内容和对照多个来源。当前版本、报价、政策和进展要依据最新能找到的原文判断。摘要只用于找线索，无法核查的现状留作未知。可在“AI 配置 → 联网”选择搜索服务。

写正文前会应用作者已确认的语气、写作 DNA、历史表现和其他写作约定，再结合素材、已读网页和提纲成稿。一次候选生成最多执行两次搜索、三次网页阅读、两次定位或对照，模型与工具调用可能分别计费。

## 中断处理

- 首包或上游空闲超时为 120 秒，单次候选请求总期限为 10 分钟；下行每 15 秒发送 SSE 心跳。浏览器连续 45 秒没有收到任何网络数据时退出等待。
- 每约一秒有新内容时写入候选检查点，结束、错误和用户取消时再次保存。进程异常退出后，重新读取列表会把遗留生成状态标记为中断。异常退出最多可能丢失最后一段尚未写盘的内容。
- 必须收到模型 `finish_reason=stop` 或 `[DONE]` 才认为候选完成。输出上限使用 8192 tokens；遇到 `length`、提前关闭、格式损坏或缺少结束标记时保留全文，显示原因，禁止直接选用为完整稿。
- “继续生成”把原任务、素材和已经生成的正文重新交给模型，只要求续写后文。已完成的调研和提纲会复用，轨迹中会新增一次运行。其他完成稿不会重跑。续写由模型完成，仍需要人工检查接续处是否重复或语义连贯。
- 旧 `/generate/stream` 调用保持双平台协议；异常内容改存候选稿，不再把半篇内容覆盖到正文。旧接口保留对未提供结束标记的兼容服务的兼容性，新候选接口严格检查结束标记。

## 存储与接口

目录为 `DATA_DIR/generation-candidates/<user hash>/<article hash>/<uuid>.json`。用户和文章 ID 用 SHA-256 生成目录名，候选 ID 只接受 UUID 字符，接口统一经过登录鉴权和文章 ID 校验。同一文章 ID 在不同账号下互不可见。每篇文件使用临时文件加 rename 原子写入，不写 API Key 或请求头。

文件保存任务和素材快照、参考上下文、候选内容和最近 40 个轨迹步骤，供查看和续写使用。轨迹记录工具输入与实际结果，不包含系统提示词、请求头或模型的内部推理。列表返回最近 30 篇，旧文件不自动删除。备份时应将该目录和现有数据目录一同备份。回滚代码不会删除候选文件。

接口：

- `GET /api/articles/:articleId/candidates`：读取候选列表。
- `POST /api/articles/:articleId/candidates`：创建 1–3 篇候选，校验平台、数量及输入长度。
- `POST /api/articles/:articleId/candidates/:candidateId/stream`：开始或继续单篇，已完成或同篇正在生成返回 409，并发满返回 429。

并发锁在进程内维护，适配当前 `web/ecosystem.config.cjs` 的单实例 fork 模式，不支持直接扩为 PM2 cluster。密钥只在请求期内存中使用。关闭弹窗会停止当前请求，不提供关闭浏览器后继续后台生成的承诺。
