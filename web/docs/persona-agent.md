# 账号人设分析 Agent

## 目标

账号人设用于回答“作者是谁”，与回答“文章怎么写”的六层写作 DNA 分开管理。人设包含账号信息、已确认的人物经历、历史发布内容画像、说话风格、熟悉领域、稳定观点、读者关系和其他长期信息。

## 数据与确认流程

1. 用户在“账号与资产 → 写作资产”中点击“分析历史文章”。
2. 前端尽量读取最近 20 条公众号已发布记录的标题和摘要。
3. 服务端从当前用户目录读取最多 12 篇历史成稿，优先使用已经写入公众号草稿箱的文章。
4. Agent 只返回人设候选，不直接写入长期资产。
5. 用户检查、编辑并点击“保存写作资产”后，人设才保存到 `creator_writing_profile:{userId}`。
6. 关闭“生成文章时自动使用这份人设”后，已保存内容仍保留，但不会进入提示词。

## 提示词注入

`buildWritingContext()` 会把已启用的人设放在文章生成用户提示词的最前面，之后依次是中文成文底线、上下文规则、写作规范、六层 DNA、作者确认取舍、长期背景和历史表现证据。

人设不能覆盖本篇任务和素材，也不能把模型从历史文章中推测的经历写成第一人称事实。`personalExperiences` 只允许保存用户确认过的真实经历。

## API

- `POST /api/creator-profile/persona/analyze`
  - 输入：浏览器 AI 配置、可用账号信息、公众号已发布标题与摘要。
  - 输出：人设候选和本次使用的来源数量。
  - 受登录鉴权、用户隔离和高成本操作限流保护。
- `GET /api/creator-profile`
  - 返回包含 `persona` 的完整写作档案。
- `PUT /api/creator-profile`
  - 保存用户确认后的完整写作档案。

旧写作档案没有 `persona` 时会在读取时补成空人设，不需要数据库迁移。
