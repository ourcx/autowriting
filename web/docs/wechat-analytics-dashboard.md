# 微信数据看板

数据看板沿用今日头条和小红书的账号绑定方式：用户从已登录的微信公众平台浏览器导出 Cookie JSON，在“用户页 > 微信内容分析”中绑定。Cookie 只按当前工作台用户保存在浏览器 `localStorage`，刷新数据时临时发送给后端，后端不会持久化 Cookie。

## 使用

1. 在浏览器登录微信公众平台，使用可信的 Cookie 导出工具导出 `mp.weixin.qq.com` 的 JSON 数组。
2. 打开工作台“用户页”，在“微信内容分析”中粘贴 Cookie JSON 并绑定。
3. 绑定过程会立即启动一次无头浏览器采集，验证登录态。
4. 打开“数据看板”，可立即同步或开启页面内定时刷新。

Cookie JSON 示例只说明结构，不能写入真实值：

```json
[
  {
    "name": "slave_sid",
    "value": "...",
    "domain": ".mp.weixin.qq.com",
    "path": "/"
  }
]
```

也可以用本地文件执行一次离线采集：

```bash
pnpm --dir web wechat:analytics:collect ./wechat-cookies.json /tmp/wechat-analysis.json
```

Cookie 文件不应纳入 Git。采集脚本不会把 Cookie、登录链接或 token 写入结果文件。

## 自动刷新

自动刷新配置同 Cookie 一样保存在当前用户的浏览器中。数据看板打开时，会按设置间隔触发采集；关闭页面后不会在服务端保存 Cookie 或继续请求微信。每次成功采集都会保存脱敏后的历史快照，因此下次打开仍可查看历史数据和趋势。

## 数据口径

- 采集接口按 `offset/count` 翻页，直到微信返回 `next_offset=0`，最多保存 500 篇。
- 阅读指标是所选统计期内的阅读人数，不等于发布后的累计阅读。
- 同一个人阅读多篇文章时会分别计入各篇，不能把文章阅读人数相加当作账号去重人数。
- “高关注”和“低关注”按同一快照内的分位划分，只表示相对位置，不代表写作质量。
- 作者偏好来自编辑器中明确保存的“写作取舍”，不会从高阅读文章的句式自动推断。

## 故障恢复

看板会保存最后一次成功快照、最后尝试时间和错误摘要。同步失败时继续展示旧快照，并明确标出旧数据时间。登录过期后重新导出 Cookie JSON 并绑定即可。
