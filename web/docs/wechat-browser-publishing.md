# 微信草稿自动发表

公众号草稿页保留官方 API 的列表读取能力，正式发表改用微信后台浏览器流程。这样可以在提交前处理编辑页和发表弹窗里的选项，包括原创声明、留言范围和流量主广告。

## 凭据边界

- AppID 与 AppSecret 用于写入草稿、读取草稿列表和核对目标草稿。
- 微信后台 Cookie JSON 与数据看板共用，只保存在当前用户的浏览器 `localStorage`。
- 发起发表时，前端临时把 Cookie 发送给服务端。服务端只注入本次 Playwright 上下文，不写数据库、日志或截图文件名。
- 浏览器上下文在请求结束后关闭。成功和失败截图保存在 `web/data/wechat-publish-debug/`，属于运行数据，不得提交。系统不会自动覆盖或清理这些截图。

## 发表流程

服务端先用官方草稿接口按列表位置核对 `media_id`，避免列表刷新后误发其他草稿。Playwright 随后登录微信后台，打开同一位置的草稿，读取编辑页标题并再次核对。

确认目标后，自动化按用户配置处理以下选项：

- 声明原创：默认关闭。开启后会处理已知的原创确认弹窗；页面出现未知声明流程时停止。
- 留言范围：可保持草稿现状，也可设置为所有人、仅关注者或关闭。
- 流量主广告：默认保持草稿现状。开启后进入广告设置，选择“打开全部广告”并验证选中状态。
- 群发通知：固定关闭。当前能力只做普通发表，不消耗群发次数，也不处理管理员扫码。

系统在设置前、设置后、最终确认页和结果页分别截图。最终“发表”按钮只点击一次。点击后只有看到“发表成功”“发布成功”或“已提交审核”才返回成功；页面要求扫码、继续发表或没有明确结果时，接口返回状态未知，并提示先到微信后台核对，禁止自动重试。

## 草稿简介

所有工作台草稿写入入口都把文章标题写入微信 `digest`。定时任务同样使用标题作为简介，不再从正文开头截取内容。

## 配置位置

在“公众号管理 > 草稿箱”点击“发布”，会先打开发布设置。选项按当前工作台用户保存在浏览器中，下次发布继续沿用。账号页中的“后台自动化”Cookie 同时服务数据看板和草稿发表。

## 验证

```bash
pnpm --dir web test:wechat-publish
pnpm --dir web smoke
pnpm --dir web verify
```

`test:wechat-publish` 使用本地 HTML 夹具，不连接微信，也不会创建或发表真实草稿。真实账号验收必须选择测试草稿，确认群发通知关闭，并在发表后核对微信发表记录和四张截图。

## 回滚

撤销浏览器发布器、草稿页发布设置和对应 API 分支后，旧调用仍可回到 `freepublish/submit`。本功能没有数据库迁移；回滚不会修改文章、草稿和 Cookie。`web/data/wechat-publish-debug/` 中的截图继续作为运行数据保留。
