# 公众号样式与富文本渲染

公众号发布预览和样式管理页统一使用 `src/utils/wechatMarkdown.ts` 渲染 Markdown，避免预览结构与实际复制结构不一致。

## 支持的扩展结构

- 标题自动生成 `.prefix`、`.content`、`.suffix`，供主题精确装饰标题。
- Markdown 表格自动包裹为 `.table-container`。
- 普通引用块使用 `.multiquote-1`。
- GitHub Alert 写法转换为语义提示块：

```markdown
> [!NOTE] 补充说明
> [!TIP] 行动建议
> [!IMPORTANT] 核心结论
> [!WARNING] 风险提示
> [!CAUTION] 严重警告
```

- `- [x]` 和 `- [ ]` 转换为微信兼容的任务列表状态，不依赖会被微信过滤的 checkbox。
- 独占一行的 Markdown 图片转换为 `figure`；紧随其后的斜体段落转换为 `figcaption`。

## 预览与复制

预览直接注入主题 CSS。复制到公众号前会读取浏览器计算样式并写回元素的内联 `style`，同时保留提示块、表格容器、图片图注和任务列表结构。

样式管理页提供：

- 文章预览与组件总览切换。
- 手机宽度与宽屏预览切换。
- 自定义 CSS 实时预览。

## HTML 块排版

`/canvas` 默认进入 HTML 块排版模式。该模式使用纵向文档流承载完整公众号文章，并保留局部 SVG 作为 AI 可生成的装饰能力，不再要求整篇正文都绘制在 SVG 中。

块排版使用 `shared/wechatBlockDsl.ts` 定义的安全 DSL：

- `content`：通过 `sourceId` 引用标题、章节、正文、引用、列表或图片，只保存版式和内联样式；支持首行缩进、单次首字下沉和最多 3 个精确原文片段标记。标记只能匹配已有原文，无法匹配时自动丢弃。
- `section`：组合 2-8 个连续内容源，支持纵向、左右双栏、主体对比、重点加双栏、时间线、步骤流、媒体文字分栏和 2/3 列网格；双栏可通过 `columnRatio` 选择 `1:1`、`1:2` 或 `2:1`。
- `decoration`：通过 `anchorSourceId` 锚定在正文前后，仅允许经过校验的 SVG Path。
- `asset`：由 AI 提供图片生成提示词，程序固定调用图片生成服务，不接受任意远程 URL。
- `divider`：锚定在内容源前后，支持实线、虚线、点线、双线和主题双色渐变。
- `switcher`：锚定在内容源前后的双状态图片组件。AI 只提供同一构图的切换前后提示词，程序生成图片和受控 SVG 点击切换结构；微信不支持交互时仍显示首图。
- 文档宽度固定为微信正文预览宽度 677px，高度由 HTML 内容自然增长；`sidePadding` 默认 8px，可在 0-48px 内调整，并同步到复制结果。
- AI 不能返回正文、图片地址、任意 HTML 或 CSS；服务端会按文章原顺序强制回填全部内容。
- 每篇文章的块排版单独保存在浏览器本地，不覆盖 SVG 画布数据。
- 编辑器支持正文块选择、版式、颜色、字号、行高、间距、边框和图片显示方式调整。
- “复制公众号内容”会通过微信专用编译器输出稳定 HTML：先像 Markdown 复制链路一样将计算样式写成内联样式，再将双栏转为表格、图片取消裁切、SVG 装饰降级为分割线，并同时写入 HTML 与纯文本剪贴板。
- “推送公众号”复用现有草稿接口，自动处理封面和正文图片转存。展示型表格、单元格和编辑器包装层会显式清除默认边框，避免微信编辑器补出黑框；透明 SVG 图标转存为 PNG，避免 JPEG 透明区域变黑。
- 块排版优先使用文章预览中明确选择的封面。没有封面或封面上传失败时停止推送并显示错误，不再静默替换为空白默认封面。

## 受控设计输入

视觉排版不直接信任用户提示词。`shared/canvasDesignTemplates.ts` 提供杂志叙事、采访手记、多主体周报看板和设计文件驱动四类模板。每个模板除结构说明外，还包含程序可执行的 `designSystem`：主题 Token、标题规则、正文缩进、导语/正文/媒体 Section 配方和布局循环。AI 负责选择语义分组，`shared/canvasDesignSystem.ts` 负责把分组编译成统一、可复现的最终 DSL。

编辑器支持拖入 `.txt`、`.md`、`.json`、`.svg`、`.xml`、`.drawio` 文件。文件内容只作为不可信设计参考传给模型，服务端限制长度并明确禁止其覆盖正文保护、DSL 和安全规则。

Design 文件格式不固定，代码不解析或猜测其中的 Token。生成时采用两阶段 AI：第一阶段完整阅读原始文件并输出设计计划，第二阶段结合设计计划、原始文件和文章 `sourceId` 生成安全 DSL。组合区域和设计组件能力作为生成质量指引，不再因数量或背景层级不足拒绝一份结构合法的排版。

文章内容源超过 8 个时直接使用自适应分段生成：服务端按章节边界和每组最多 8 个内容源拆分，分段模型只输出 1-3 个 `sourceId` 布局决策。只有第一组允许给出一次 `theme`，后续分组禁止重复文档级字段；最终主题由可执行设计系统统一。每组独立校验并按原顺序合并；截断时递归二分，连续两次无效时仅该组改用本地安全块。最终编译器会为所有组统一套用模板 Token 和 Section 配方，因此单组降级不再产生一段默认样式。

DSL 支持文档级 `theme`，AI 可一次定义颜色、字体层级、圆角和间距，内容块自动继承，避免重复输出大量样式。组合区域支持 `editorial`、导语 `lede`、眉题 `overline`、数据强调 `metric`、顶部/左侧/底部强调边和可选阴影；边框默认关闭。

AI 生成结果会在服务端执行最小视觉归一化：只把 `secondary`、`accent`、图标、装饰、分隔线和 marks 收敛到 `primary`，并清除 content、section 和 itemStyles 的完整边框。背景、纹理、阴影、布局、字号、字重、间距、圆角和特殊文字角色均保留，避免安全归一化抵消设计结果。

最终文档会经过视觉质量门禁，检查内容源唯一覆盖、组合区域数量、布局节奏、背景/强调/图标/素材手段和文字角色层级。未通过时不再调用 AI 重试整篇，而是使用模板设计系统确定性重建；`pnpm --dir web test:canvas` 固定验证四套模板的视觉签名、主色、边框、内容顺序和归一化保真规则，并已纳入 `verify`。

Section 可引用内置 Lucide 图标白名单，也可使用 AI 生成并通过 Path 校验的图标。复制和推送时图标会转换为内联图片，避免微信直接清洗 SVG。每个 `sourceId` 仍有独立 `itemStyles`，用户可继续手动修改。

文档和 Section 均支持受控 `surfaceStyle`：纯色、线性渐变、斜向条纹、点阵、网格、横线稿纸和 AI 生成背景。生成背景只接受提示词、图片比例、铺设方式及遮罩参数，图片 URL 由程序绑定到固定生成服务，不开放任意 CSS 或远程地址；复制时保留背景样式，推送时服务端只识别该固定域名并转存为微信内容图片。

带背景或完整边框的 content、section 和 `itemStyles` 会自动保证至少 12px 内边距，避免文字贴边。左右留白通过外层无边框表格单元格输出，避免微信编辑器清洗根节点 padding 或普通 div margin 后失效。

正常长度文章会提示 AI 主动组合布局、画布背景、短内容背景、强调边/图标、特殊文字角色、素材或装饰等能力；最终是否可用由视觉质量门禁判断，不再仅以 JSON 合法作为成功条件。

非 Markdown 质量校验会拒绝把普通长正文包装成引用块的结果：`quote` 只用于原文引用内容源；连续 3 段以上正文不得放入 `callout`、左侧粗线或大圆角浅色面板。背景层级由画布和少量短导语、数据、图文组件承担，长阅读区保持无框，并通过 editorial、media-text、grid、divider、asset、marks 等组件建立视觉节奏。

## 非 Markdown 编辑器参考

- [`tiptap-appmsg-editor`](https://github.com/KID-1912/tiptap-appmsg-editor)：借鉴其 `section / p / span / img` 内容约束、样式组件插入、分隔线、首行缩进和富文本节点设计。
- [`OpenSVG`](https://github.com/cailven/opensvg)：借鉴其组件注册表、组件树、属性面板、移动端预览和项目序列化思路。
- OpenSVG 的点击切换被收敛成独立 `switcher` 素材组件，不允许承载或隐藏正文；不引入任意 HTML、零高覆盖和伸展正文动画。
- 不直接引入 Tiptap 作为第二套正文状态源。文章正文仍由 `CanvasSource` 唯一管理，DSL 只保存可验证的视觉组件和 `sourceId` 映射。

Markdown 预览继续使用原有 `renderWechatMarkdown()` 和主题 CSS，不读取块排版数据，两种流程互不影响。

## SVG 画布

`/canvas?mode=svg` 作为自由画板保留原有 SVG Scene Graph。画布使用 `shared/canvasDsl.ts` 定义的 JSON DSL，并通过 SVG 渲染。进入画布时需要选择一篇公众号文章；从文章预览进入时会自动携带当前 `articleId`。

当前支持：

- `text`：文字、字号、颜色、对齐和行高。
- `text.variant`：plain、banner、card、quote、sticky 五种公众号内容面板。
- `image`：多图 URL、cover/contain 和圆角。
- `shape`：矩形、椭圆、填充和描边。
- `path`：由 AI 根据文章主题生成安全 SVG Path，可组合为采访、手帐或其他主题插画。
- 节点拖拽、图层排序、属性编辑、DSL 编辑、自动保存。
- 文章 Markdown 自动拆分为标题、章节、正文、引用、列表和图片内容源。
- AI 只生成引用 `sourceId` 的布局，不生成或改写正文和图片地址。
- 服务端强制回填原文，并将 AI 漏排的内容按文章顺序追加。
- 内容节点统一使用 50px 左边距和 650px 宽度；共享字宽算法负责换行与高度计算，避免左右不齐和文字越界。
- 初始文章画布宽度为 750px，高度支持 320-32000px 手动输入、100px 步进和自动适应内容。
- AI 生成的自由画板支持 750-1280px 宽度；服务端重新计算文字高度、夹紧边界并消解内容节点碰撞。普通文章初始画布仍为 750px。
- 复制 DSL、下载 SVG 源文件和下载公众号 PNG 长图；超过 6000px 时自动分段。
- 推送公众号时自动将画板分段光栅化为 PNG，并通过现有草稿接口转存为微信正文图片。

AI 提示词只声明自由画板实际支持的 `text`、`image`、`shape`、`path` 节点，不再误导模型输出仅块排版支持的 theme、section、asset 或图标字段。AI 不允许输出任意 HTML、JavaScript、SVG 标签、正文或图片地址。`path.d` 只接受标准 SVG 路径命令、数字和分隔符，并限制长度与节点边界。服务端和前端都会重新解析 DSL；公众号内容本身不依赖 AI 返回，避免模型省略或虚构。

后续可在此模型上继续增加缩放、吸附参考线、撤销栈、组合、多选，以及将 PNG 直接写入公众号素材库。

完整架构决策见 [`adr-visual-board-architecture.md`](adr-visual-board-architecture.md)。
