## 给请求加日志的标准方式

### 1. 导入 logger

在路由文件顶部导入：

```ts
import { logger } from '../logger.js'
```

> 注意：本项目是 ESM + `.ts`，导入路径**必须带 `.js` 后缀**（即使源文件是 `.ts`）。

### 2. 四个级别的调用签名

```ts
logger.debug(module, message, data?)   // 调试细节，默认不输出（LOG_LEVEL=INFO 时被过滤）
logger.info(module,  message, data?)   // 关键流程节点
logger.warn(module,  message, data?)   // 非致命异常/降级
logger.error(module, message, data?)   // 错误（必须搭配 catch）
```

- 第 1 参数 `module`：**大写常量字符串**，标识模块。如 `'RAG'`、`'SCORES'`、`'TOUTIAO'`、`'MONITORING'`。
- 第 2 参数 `message`：人类可读的中文描述。
- 第 3 参数 `data`（可选）：结构化对象，放错误详情、入参摘要、耗时等。**不要把整个 req/res 塞进去**。

### 3. 一个请求应该加日志的标准位置

以 `rag.ts` 的 `/search` 接口为例，改造前后对比：

**改造前（现状，违规）：**
```ts
router.post('/search', async (req, res) => {
  try {
    const { query, topK = 5 } = req.body
    if (!query) return res.status(400).json({ error: '缺少 query' })
    const results = await retrieveRelevant(searchQuery, { ... })
    res.json({ results, meta: { ... } })
  } catch (err) {
    res.status(500).json({ error: err.message })
  }
})
```

**改造后（标准写法）：**
```ts
import { logger } from '../logger.js'   // 顶部导入

router.post('/search', async (req, res) => {
  const userId = req.user.id
  try {
    const { query, topK = 5, scoreThreshold } = req.body
    if (!query) {
      logger.warn('RAG', 'search 缺少 query 参数', { userId })
      return res.status(400).json({ error: '缺少 query' })
    }

    logger.info('RAG', '搜索请求', { userId, topK, scoreThreshold: scoreThreshold ?? null })
    const searchQuery = extractSearchQuery(query) || query
    const results = await retrieveRelevant(searchQuery, { topK, scoreThreshold, aiConfig, userId })

    logger.info('RAG', '搜索完成', { userId, count: results.length })
    res.json({ results, meta: { topK, count: results.length, ... } })
  } catch (err) {
    logger.error('RAG', '搜索失败', { userId, error: err.message })
    res.status(500).json({ error: err.message })
  }
})
```

### 4. 日志埋点清单（按请求生命周期）

| 位置 | 级别 | 说明 |
|------|------|------|
| 请求入口 | `info` | 记录关键入参（userId、标识符），**别记完整 body** |
| 参数校验失败 | `warn` | 记录哪个参数缺失/非法 |
| 关键中间步骤 | `debug` | 子任务开始/完成，默认不输出，排查时开 `LOG_LEVEL=DEBUG` |
| 外部调用前/后 | `debug`/`info` | 调 LLM、爬虫、第三方 API 前后 |
| 请求成功 | `info` | 记录产出规模（count、字数等），便于统计 |
| `catch` 里 | `error` | **必须** `logger.error('MODULE', '描述', { error: err.message })` |
| 降级/兜底 | `warn` | 如 Jina 失败降级直爬、Chromium 启动失败回退 Edge |

### 5. 错误捕获的强制模板

项目规范要求所有 `catch` 必须用 logger，**禁止 `console.error`**：

```ts
} catch (err) {
  logger.error('RAG', '操作描述', { error: err.message })
  res.status(500).json({ error: err.message })
}
```

如果 `err` 不确定类型，用断言取 message（与 logger.ts 自身写法一致）：
```ts
} catch (e: unknown) {
  const err = e as Error
  logger.error('RAG', '操作失败', { error: err.message })
}
```

### 6. 性能监控（可选，给耗时操作加）

对于 LLM 调用、索引构建等慢操作，用 `monitor` 包裹，自动记录耗时和内存：

```ts
import { monitor } from '../logger.js'

const result = await monitor(
  'rag-retrieve',                              // 操作名
  () => retrieveRelevant(searchQuery, { ... }), // 要执行的异步函数
  'RAG'                                         // module（默认 'PERF'）
)
```

会自动输出类似：
```
[INFO] [RAG] ✓ rag-retrieve 完成 { operation: 'rag-retrieve', duration: '342ms', memory: '0.12MB', status: 'success' }
```
