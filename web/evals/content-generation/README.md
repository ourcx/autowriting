# 内容生成评测集

这套评测用于比较文章模型、提示词、RAG 配置和生成流程。它评估“能否产出可信、符合作者风格、可进入发布流程的内容”，不评估搜索服务覆盖率、平台发布成功率或文章发布后的阅读表现。

`dataset.v1.jsonl` 当前包含 40 条中文样本：

| 分类 | 数量 | 主要风险 |
| --- | ---: | --- |
| `factuality` | 8 | 数字、单位、实体、时序、因果和结论强度 |
| `conflict_resolution` | 4 | 本篇素材、长期记忆与旧 RAG 内容冲突 |
| `style_alignment` | 6 | 写作 DNA、禁用表达、术语和叙述身份 |
| `audience_structure` | 5 | 受众问题、篇章顺序和行动性 |
| `rag_boundary` | 5 | 旧事实串稿、重复召回和提示注入 |
| `platform_adaptation` | 4 | 公众号母稿与今日头条版本的事实一致性 |
| `publishability` | 4 | Markdown、来源、健康承诺和输出污染 |
| `robustness` | 4 | 缺数据、长度压力、噪声和中断续写 |

## 数据格式

每行是一个独立 JSON 对象：

- `task`、`materials`：送入生成接口的本篇任务和素材。
- `context.creator_profile`：与六层写作 DNA 对齐的当前样本偏好。
- `context.long_term_memory`：稳定背景，只能在不与本篇素材冲突时使用。
- `context.retrieved_context`：手动选择或自动召回的往期内容。
- `context.source_article`：今日头条改写或中断续写使用的母稿。
- `expected.required_facts`：必须保持的原子事实及证据位置。
- `expected.must_include`、`must_not_include`：适合确定性检查的约束。
- `expected.style_rules`、`structure_rules`、`publish_rules`：供盲评使用。
- `expected.review_focus`：争议时的人工复核重点，不直接送给被测模型。

评测运行器必须保存模型、服务商、提示词版本、代码 commit、数据集版本、温度、最大输出 token、RAG 模式和原始输出。默认每条只生成一次，不因评分低而自动重试；需要测稳定性时，单独运行多种子实验。

## 指标口径

### 事实性

先把输出拆成可以核验的原子主张，再根据 `materials`、允许使用的上下文和 `required_facts` 标注：

- `supported`：证据直接支持，实体、数字、单位、范围、时序和因果方向一致。
- `qualified`：输出明确标为推测、待核实或条件判断，且没有扩大证据强度。
- `unsupported`：材料没有依据，但输出写成事实。
- `contradicted`：与证据冲突，或改错实体、数字、范围、因果方向和结论强度。

主指标：

```text
事实支持率 = supported 主张数 / 全部可核验主张数
必要事实覆盖率 = 已正确表达的 required_facts / required_facts 总数
严重事实错误率 = 出现关键 contradicted 或 unsupported 主张的样本数 / 有效样本数
```

`qualified` 单独报告，不用它抬高事实支持率。标题、摘要和正文同样参与核验。关键数字、政策、价格、健康结论、人物经历和发布状态一旦冲突，该样本事实门禁直接失败。

### 风格符合度

只评价样本中适用的规则。盲评员按 0–4 分评估：

- 词句与节奏
- 篇章结构
- 切入视角
- 素材选择
- 观点与判断
- 图文与视觉要求

```text
风格符合度 = 各适用维度得分之和 / 各适用维度满分之和 × 100
```

禁用表达、虚构第一人称经历、擅自替换专业术语等可确定判断的项目另做硬门禁。历史高低表现只能作为选题证据，不能因为“像高阅读文章”而增加风格分。

### 可发布率

盲评员回答一个问题：这篇内容是否只需机械校对，就能进入对应平台的发布准备阶段？

“可发布”必须同时满足：

- 事实门禁通过。
- 无需补做外部事实调查。
- 无需重写标题、开头、主要结构或结论。
- 人工只需处理错别字、标点、链接和少量措辞，预计不超过 5 分钟。
- Markdown、标题层级、来源、平台限制和内容合规检查通过。

两名评审独立给出 `pass/fail`；意见不一致时由第三名评审裁决。

```text
可发布率 = 最终判定为 pass 的样本数 / 有效样本数
```

同时保存失败原因标签，例如 `fact`、`style`、`structure`、`format`、`compliance`，避免只看一个比例。

### 人工修改量

被测输出和作者确认后的最终稿都要保留。不要用文章搁置时长代替编辑时长。

主指标：

- 归一化编辑距离：使用成熟 diff 库计算字符插入、删除和替换量，再除以两版正文的较长字符数。
- 修改段落率：发生实质变化的段落数除以最终稿段落数。
- 活跃编辑时长：页面可见、获得焦点且最近 30 秒有键盘、输入、点击或滚动时累计的分钟数。
- 结构重写率：标题、开头、主要章节顺序或结论被重写的样本比例。

项目已有 `activeEditingMs`、`changedParagraphs` 和 `retainedParagraphs`，但当前段落统计基于“整段原样包含”，适合趋势观察，不足以替代正式 diff。

### 生成成本

成本按模型和价格版本计算，不能统一套用 GPT-4o 的固定单价。

```text
单次调用成本 = 输入 token × 输入单价 + 输出 token × 输出单价 + 服务商固定调用费
入选文章成本 = 该批全部候选、失败调用、续写和平台改写的实际成本之和
```

远程 Embedding、付费搜索、公众号采集和图片生成单独记账，不混入“正文生成成本”。每条记录至少包含服务商、模型、价格版本、币种、输入/输出 token、缓存 token、请求状态和候选 ID。

当前 `token_usage` 能按用户记录模型和 token，但部分流式路径只按字符数估算输出 token，且前端成本页固定使用 GPT-4o 参考价。正式成本评测前需要补齐真实 usage 和版本化价格表。

### 时延

成功和失败请求分开统计，统一报告 P50、P95：

- 排队时延：任务创建到获得并发槽位。
- 首字时延：获得并发槽位到首个正文 chunk。
- 生成时延：获得并发槽位到 `done`。
- 入选文章时延：一批任务开始到至少一篇可选完整稿完成。
- 双平台时延：公众号母稿开始到对应头条稿完成。

候选稿已有 `createdAt`、`firstChunkAt` 和 `finishedAt`，但缺少独立的 `startedAt`，因此当前只能把排队和执行时间合在一起。正式评测应增加 `startedAt`，并记录模型请求、RAG 和写盘三个阶段。

## 建议门禁

这些是首轮基线前的建议值，不代表项目已经达到：

- 严重事实错误率为 0。
- 事实支持率不低于 98%，必要事实覆盖率不低于 95%。
- 风格符合度平均不低于 80，硬性禁用表达零命中。
- 可发布率不低于 85%。
- 人工修改量、成本和时延先跑固定模型基线；后续版本不得以降低事实性或可发布率换取表面改善。

40 条样本适合开发期回归，不足以单独证明线上泛化能力。稳定后应从真实生产稿中按主题、长度和平台分层抽样，扩展到至少 200 条，并保留一组不参与提示词调优的隐藏测试集。

## 静态校验

静态校验不调用模型，也不会产生费用：

```bash
pnpm --dir web test:content-eval
```

它检查条数、ID、分类分布、平台值、上下文字段和评审规则是否完整。
