的学生，在大三结束前至少有一段实习经历。而在五年前，这个比例可能还不到一半。这不是内卷，是新的「门票」很多人觉得，这是学生在「卷」。但我认为，这更像是一种被环境重塑的生存策略。计算机行业的招聘逻辑，这几年彻底变了。实习，已经从「锦上添花」的加分项，变成了「入场必备」的门槛项。我秋招时和一位大厂 HR 聊过，他直言：「现在收一百份简历，先筛掉所有没实习经历的，可能就只剩三十份了。我们没时间从零培养一张白纸。」企业这个选择很现实。一个有过实习的学生，至少证明了三件事：他能通过招聘流程，他适应过真实工作环境，他有基本的协作和交付能力。这比单纯看绩点和学校背景，效率高得多。我见过最夸张的一份简历，来自一位大四学生：三段大厂实习，两个开源项目核心贡献，一个算法竞赛奖。他最后拿了五个 分，不代表你能写出健壮的后端服务。而实习，就是最直接的「能力试金石」。我第一段实习时，mentor 让我改一个简单的 API 接口。我照着学校教的 MVC 模式写，自认为很规范。结果他看了一眼就说：「你这没加熔断和降级，线上流量一来就挂了。」那一刻我才明白，课堂和生产线之间，隔着一道巨大的鸿沟。第二，招聘链路前移了。 现在的校招，早就不是大四开学才启动。它是一条完整的链条：日常实习（大二/大三） 站上刷到「大一计算机学习路线图」、「大二进大厂实习攻略」。大家清楚地看到了「路径」，也看到了「竞争」。当你知道同龄人已经在刷 LeetCode、做项目时，很难安心只啃课本。我踩过的三个坑我支持早实习，但不是盲目地早。我自己和身边朋友，都走过弯路。坑一：基础不牢，地动山摇。 我有个同学，大一下学期就托关系进了一家小公司实习。结果每天的工作就是复制粘贴数据、整理文档。两个月下来，技术没学到，课程还挂了三门。他后来跟我说：「我连数据结构都没学明白，去实习就是打杂，纯粹浪费时间。」我的建议是：至少掌握一门编程语言的核心语法，了解基本的数据结构（数组、链表、哈希表），再去投简历。否则，你接不住有技术含量的活。坑二：只看公司名气，不看岗位内容。 我大二时拿到两个实习 offer：一个是大厂的测试开发，一个是创业公司的后端开发。我毫不犹豫选了大厂。进去后发现，我的工作是写自动化测试脚本，每天和固定的框架打交道，接触不到核心业务逻辑。而那个去创业公司的同学，三个月就从写接口做到参与系统设计。名气是给别人看的，成长是自己的。选岗位，一定要看具体做什么，能不能学到东西。坑三：把实习当终点，而不是起点。 我见过一些学生，刷了一段大厂实习经历，就觉得自己稳了。秋招时，简历上除了那段实习，项目经历一片空白。面试官一问细节，就露馅了。实习的真正价值，是帮你校准方向、发现短板。我第一段实习后，就意识到自己工程能力太弱，于是回来猛补了 Docker 和 Linux
